Reviewed 13 November 2026 Sydney. This is a recovery runbook and evidence register, not certification that production data has been restored.

Match byte size and SHA-256, then authenticate as owner and another user to test download denial. |

Supabase database backups include Storage metadata, not the stored object bytes. Follow the [official backup guide](https://supabase.com/docs/guides/platform/backups) and [object download guide](https://supabase.com/docs/guides/storage/management/download-objects). A database rollback alone cannot recover deleted files.

Never run restore commands against the live project as a test. Record the exact source snapshot, object manifest, environment, results, recovery time and reviewer before marking data recovery complete. Keep backups encrypted and private. Do not attach customer data to Git or CI artifacts.

Read-only checks of AVES Shared Accounts on 13 November found no health advisories. Security advisories show informational RLS-with-no-policy notices on private server-only tables, plus disabled leaked-password protection. Deny-all RLS must not be weakened to clear an informational notice. Password protection remains an explicit configuration follow-up, not a completed fix. [Supabase guidance](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
