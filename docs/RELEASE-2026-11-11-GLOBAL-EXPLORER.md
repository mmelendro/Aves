## Visitor behavior

Country and region selection now updates the same global explorer from native Australian entry pages as well as the main app. The Australian homepage, all nine regional guides and directory use the shared public frontend. Existing editorial material appears only for its matching initial scope. The fixed Australian header has an explicit spacer so headings remain visible.

On aves.bio, public history paths follow scope: `/` for world, `/australia`, `/colombia`, `/new-zealand`, `/regions/{id}`, `/australia/regions/{id}` and `/new-zealand/south-island`. Other NZ island scopes retain their query at `/new-zealand`. Validated `explore` and `region` query state survives reload and browser history. Preview hosts retain their current path so isolated deployments remain reloadable. Private answers and wishes are excluded from public URL state.

My Trips links use the existing shared account with selected country/region context. This remains private planning with quotes and personal confirmation, not instant confirmed bookings or a combined multi-country checkout. No booking/backend schema or auth behavior changed.

## Source boundary

Australia receives a pinned public-only frontend snapshot under `components/public-explorer`, generated by `scripts/sync-public-explorer.py`. Its manifest records source/output hashes for 113 files and source provenance. Host adapters reuse the existing media, discovery and header contexts, UI utilities and brand artwork. There is one existing media provider/player, not a second player. Public main assets are absolute aves.bio URLs; Australian catalogue images/calls retain the `/australia` asset prefix. No package or lockfile change, paid provider, database, auth, billing or deployment-protection change was introduced. This bridge does not merge the independently deployed applications or their backend trees.
