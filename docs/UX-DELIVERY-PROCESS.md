# AVES UX-first delivery process

Owner direction, 10 November 2026. Use small agile increments and Utzon's
connection to natural context when it helps the visitor understand a place.
Apply the ecotourism brief through clear planning, accurate local representation,
accessible controls, lawful attribution and respect for wildlife and communities.
B Corp stewardship is a values reference, never an unsupported certification claim.

## Select one useful increment

1. Start from a visitor task and concrete friction. Write the expected improvement
   in one sentence, then a short acceptance check. Current task: see the selected
   area clearly without hiding the satellite image.
2. Rank by user value, accessibility, evidence confidence and effort. Fix broken
   behaviour before visual decoration. Honour the owner's latest selected order.
3. Inspect fresh history, current handoff and working trees. Keep two apps separate.
   Define exact routes, owners, source data, uncertainty and rollback target.
4. Build the smallest complete vertical slice using existing data and components.
   Let real terrain, water and local behaviour shape decoration. Match AVES line
   weight, typography, control sizes and quiet visual hierarchy. Avoid invented
   geographic accuracy, forced wildlife, duplicate horizons and excessive animation.
5. Validate actual desktop and narrow browser layouts, keyboard focus, reduced
   motion, native links, source credits and zoom. Use appropriate automated checks.
   Record physical-device limitations rather than claiming untested touch behaviour.
6. Review the completed result, release only within current explicit authorization,
   verify production, reconcile source/docs/checkpoints, then choose the next slice.

## Definition of done

Source and docs agree; expected routes work; no private-data/provider/account
changes occurred outside scope; all required checks pass; remaining uncertainty
is explicit. A preview is not a release. A generated concept is not browser proof.

## Safe cleanup

Trace references before deleting a file, route, asset, export or dependency.
Separate proved dead code from historical documents, rollback evidence, retained
roadmap items and deferred integration work. Remove confirmed local clutter and
unused code, fix discovered defects, preserve archives, and avoid unrelated broad
rewrites. Do not describe a bounded review as a complete security audit.
